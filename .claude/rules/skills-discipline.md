# Skill Discipline

- Before implementing, debugging, reviewing, or rewriting docs, inspect `.claude/skills/` and load the smallest matching set of project skills.
- Prefer project skills over repeating long workflows in chat.
- For planning non-trivial work, use `shared-writing-plans`.
- For bugs, broken tests, or unexpected behavior, use `shared-systematic-debugging`.
- Before claiming a fix is complete, use `shared-verification-before-completion`.
- If no project skill fits cleanly, follow the matching subtree instructions and say which fallback you used.
